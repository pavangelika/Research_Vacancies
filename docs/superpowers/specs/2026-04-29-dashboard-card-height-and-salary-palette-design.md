# Dashboard Card Height And Salary Palette Design

Date: 2026-04-29

## Goal

Сделать все карточки дашборда одинаковой высоты на desktop, улучшить вертикальный ритм за счёт центрирования содержимого внутри карточек, и перевести график `Зарплаты` на цвета из основной палитры `:root`.

## Scope

- Выровнять все карточки блока `dashboard overview` по одной общей высоте на desktop.
- Оставить заголовок карточки сверху, а содержимое под заголовком вертикально центрировать.
- Не включать принудительное выравнивание по общей высоте на mobile.
- Перевести цвета точек, подписей и связанных legend/track элементов зарплатного графика на цвета основной палитры.
- Синхронно применить изменения в `reports/*` и `reports/static/*`.

## Non-Goals

- Не менять порядок карточек.
- Не менять структуру контента внутри карточек сильнее, чем нужно для общего layout-контракта.
- Не перерабатывать остальные графики сверх этой задачи.

## Approaches Considered

### 1. CSS-only equal height without content contract

Быстро, но часто даёт визуально разные внутренние вертикальные ритмы и не решает аккуратное центрирование содержимого.

### 2. Equal-height cards with a shared card-body layout contract

Рекомендованный вариант. Карточки получают общую высоту на desktop, заголовок остаётся сверху, а контент под ним центрируется в доступной области. Это улучшает читаемость без JS-замеров.

### 3. JavaScript-based runtime height syncing

Даёт полный контроль, но не нужен здесь. Сложнее, хрупче, хуже для адаптивности.

## Approved Design

### Equal Height Dashboard Cards

На desktop все карточки overview-дашборда должны визуально стать одной высоты. Источник высоты — самая высокая карточка в общем наборе карточек overview, то есть фактически все карточки левой и правой колонок выравниваются между собой.

Реализация должна опираться на существующий CSS layout overview и не вводить JS-измерения.

### Vertical Alignment Contract

- Заголовок карточки остаётся у верхнего края карточки.
- Вся область ниже заголовка становится отдельной flex/grid-зоной.
- Контент этой зоны центрируется по вертикали внутри карточки.
- Для карточек со сложным графическим наполнением центрирование должно происходить на уровне body/host-контейнера, а не через ручные margin hacks.

### Mobile Behavior

На mobile общий equal-height режим отключён. Карточки остаются естественной высоты, чтобы не создавать большие пустые вертикальные зоны.

### Salary Chart Palette

График `Зарплаты` должен использовать цвета из основной палитры `:root`, а не отдельный локальный набор вроде `SALARY_GRADIENT_COLORS` с несогласованными оттенками.

Новая привязка должна использовать уже существующие базовые palette tokens, например:

- `--palette-cyan`
- `--palette-blue`
- `--palette-purple`
- `--palette-orange`
- `--palette-green`

Конкретное сопоставление групп зарплатных значений может остаться градуированным по порядку точек, но источник цветов должен быть только из основной палитры.

### Integration Rules

- Изменения layout должны затрагивать только dashboard overview cards.
- Existing card title markup сохраняется.
- Salary color source централизуется и синхронно обновляется в source/static JS.

## Testing

- Проверить на desktop, что все overview cards одинаковой высоты.
- Проверить на desktop, что заголовки остаются сверху, а содержимое ниже заголовка центрируется по высоте карточки.
- Проверить на mobile, что equal-height принудительно не включается.
- Проверить, что зарплатный график использует цвета из основной палитры и не возвращается к посторонним локальным оттенкам.
- Прогнать существующие UI regression tests и обновить ожидания только при необходимости.

## Risks

- Центрирование может конфликтовать с карточками, у которых внутренние host-контейнеры уже задают собственную высоту.
- Слишком агрессивный equal-height layout может повлиять на overflow внутри графиков.
- Salary chart может остаться частично на старых локальных цветах, если обновить только один renderer.

## Implementation Notes

- Предпочтительно использовать единый layout-контракт `.dashboard-card` / `.dashboard-card-body` / host-контейнеров вместо специальных правил на каждую карточку.
- Для salary chart желательно заменить локальный набор `SALARY_GRADIENT_COLORS` на palette-backed array из существующих `:root` цветов.
