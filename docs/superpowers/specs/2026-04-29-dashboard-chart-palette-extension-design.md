# Dashboard Chart Palette Extension Design

Date: 2026-04-29

## Goal

Добавить новый переиспользуемый набор цветов в основную палитру дашборда и перевести на него графики `Отклики` и `Анализ работодателей`.

## Scope

- Расширить базовую CSS-палитру в `reports/styles.css` и `reports/static/styles.css`.
- Добавить `8` новых цветов как именованные CSS-токены.
- Убрать хардкод этих цветов из рендера `Откликов` и `Анализа работодателей`.
- Перевести оба графика на использование общей палитры через централизованное сопоставление.

## Non-Goals

- Не менять палитру остальных графиков.
- Не удалять старые palette/accent токены, которые уже могут использоваться в других местах.
- Не вводить отдельную вторичную chart-палитру поверх текущего `:root`.

## Approaches Considered

### 1. Inline hex only in target charts

Быстро, но ухудшает переиспользование и снова размазывает палитру по JS.

### 2. Extend the main dashboard palette

Рекомендованный вариант. Новые цвета объявляются в существующем palette-блоке `:root`, после чего `Отклики` и `Анализ работодателей` используют только эти токены.

### 3. Separate chart palette namespace

Гибче, но сейчас избыточно. Для текущей задачи это лишний слой абстракции.

## Approved Design

### Palette

В основную палитру добавляются токены для следующих цветов:

- `#00ABCB`
- `#D47CEA`
- `#F10096`
- `#007EDE`
- `#00BD00`
- `#9C41E5`
- `#D24DEE`
- `#FF9200`

Токены будут объявлены рядом с существующими `--palette-*`, чтобы их можно было переиспользовать в других карточках и элементах дашборда.

### Responses Funnel

График `Отклики` остаётся плоским, без градиентов. Каждая стадия получает цвет из новой общей палитры через централизованное сопоставление, а не через inline hex, разбросанные по коду.

### Employer Analysis

`Анализ работодателей` остаётся bar-based, без градиентов. Цвет каждой группы задаётся из новой общей палитры тем же принципом: сначала централизованное сопоставление, затем использование в рендере. Белый текст на барах сохраняется.

### Integration Rules

- Источник истины по новым цветам: CSS custom properties в основной палитре.
- JS использует именованные palette keys, а не прямые hex.
- Изменения синхронно вносятся в `reports/*` и `reports/static/*`.

## Testing

- Проверить, что `Отклики` и `Анализ работодателей` не используют gradients.
- Проверить, что оба графика используют только новые palette colors.
- Проверить desktop и mobile в браузере.
- Прогнать существующие UI regression tests и обновить их только если старые ожидания противоречат новому palette-контракту.

## Risks

- Несинхронность между `reports/*` и `reports/static/*`.
- Частичное сохранение старых hex в JS.
- Непрозрачные имена токенов, если не придерживаться текущего стиля `--palette-*`.

## Implementation Notes

- Предпочтительно завести один helper/mapper для palette-keys в JS, вместо отдельных наборов хардкода на каждый график.
- Имена токенов должны быть пригодны для повторного использования вне этих двух графиков.
